Development SDK: get it and flash it

The duo-s-playground repository is the Beitlab framework and SDK for the Milk-V Duo S. It holds a flashable Linux image, a PlatformIO platform for the C906 real-time core, the beitlabduino setup()/loop() library and a set of examples. This page takes you from nothing to a program running on the board, over Wi-Fi.

About 40 minutesMilk-V Duo S + microSDWi-Fi, Ethernet or serialSame steps on the Robotics Board and on a bare Duo S

What you get

The SG2000 chip in the Duo S has two processors. The SDK uses both, and you only ever restart the small one.

Cortex-A53

Linux image

Boots from the microSD card with Wi-Fi, SSH, mDNS (beitlab-milkv-duo.local) and the rtos-agent installed and enabled from the first boot.

C906

Your program

A FreeRTOS program you write in C. PlatformIO builds it on your PC and uploads it over SSH. Linux and your SSH session stay up while it restarts.

PC

Framework

A PlatformIO platform, the beitlabduino library, hardware profiles that protect the carrier's pins, and the examples.

The robot control core lives in a separate project. This SDK does not build the balance controller or the motor drivers: it is the open framework for your own code. See Examples and platforms for what runs where, and Write your own code to start a project.

1. Get the SDK

  1. Install the PC toolsOn Ubuntu, Debian or WSL2: 
    $ sudo apt install git python3 python3-pip mtools openssl
$ pip install platformio
    On macOS use brew install mtools git python3. The imager needs Python 3.9 or newer.
  2. Clone the repository 
    $ git clone https://github.com/beitlab-inc/beitlab-os-milkv-duo-sdk.git duo-s-playground
$ cd duo-s-playground
$ cat VERSION             # the image version this checkout matches, e.g. 0.4.1
    Everything below is run from this folder.
  3. Download the imageFrom the repository's Releases page, download beitlab-robotics-milkv-duo-os-<version>-duos-arm64-sd.img (it may be .img.xz or .img.gz) and SHA256SUMS into ~/Downloads. Check it: 
    $ cd ~/Downloads && sha256sum -c SHA256SUMS --ignore-missing
# expect: beitlab-robotics-milkv-duo-os-0.4.1-duos-arm64-sd.img: OK
    The guided imager can also download and verify the latest published release for you, so you can skip this step if you use it (option A).

2. Preconfigure Wi-Fi and write the card

The unmodified image holds no network credentials. You add yours to a personal copy before it is written, so the board joins Wi-Fi on its very first boot. Choose one option. A is the easiest.

The card is erased

Every option below overwrites the whole card. Check the device name twice: naming your computer's own disk destroys it. A personal image contains your Wi-Fi key in derived form, so keep it private and never publish it.

Option A: the guided beitlab Imager (Linux and macOS)

One interactive tool checks the image, asks for the Wi-Fi settings, finds the card, writes it and reads it back to verify.

$ python3 scripts/beitlab-imager.py --image ~/Downloads/beitlab-robotics-milkv-duo-os-0.4.1-duos-arm64-sd.img

Run it as your normal user: it asks for administrator rights only to write the disk. It goes through four steps:

  1. ImageVerifies the SHA256 against the .sha256 file or SHA256SUMS next to the image. Otherwise paste the release checksum or pass --sha256 <digest>.
  2. Board settingsEnter the Wi-Fi name and your two-letter country code (for example CO, US, ES), then the password at a hidden prompt. Optionally set a hostname such as robot-01, point to your ~/.ssh/id_ed25519.pub public key, and set a unique administration password (12 characters or more). Passwords never appear in shell arguments or logs.
  3. CardPick the removable drive from the list by number. Insert the card and press r to refresh. System disks, read-only media and mounted storage are blocked.
  4. FlashReview the summary and type the full phrase shown, for example ERASE /dev/sdc. A partial answer asks again. The writer unmounts the volumes, writes, flushes and verifies the checksum by reading back.

Useful variations:

$ python3 scripts/beitlab-imager.py --list-drives                     # see removable drives, nothing is written
$ python3 scripts/beitlab-imager.py --image my.img --dry-run          # everything except writing
$ python3 scripts/beitlab-imager.py --image my.img --prepare-only --output ~/Downloads/my-duo.img
$ python3 scripts/beitlab-imager.py --flash-only --image ~/Downloads/my-duo.img   # burn a prepared image
$ python3 scripts/beitlab-imager.py                                      # no --image: download the latest release

Add --no-emoji or --no-color for plain output. Without --image, the imager downloads the latest published release and verifies it before use; a public release needs no GitHub account.

Option B: configure an image, then flash it with any tool

This works on Linux, macOS and WSL2 and lets you use the flashing tool you prefer.

  1. Create the personal image 
    $ python3 scripts/configure-image.py \
    --image ~/Downloads/beitlab-robotics-milkv-duo-os-0.4.1-duos-arm64-sd.img \
    --output ~/Downloads/my-duo.img \
    --ssid "Your network" --country CO \
    --hostname robot-01 --ssh-key ~/.ssh/id_ed25519.pub --user-password
    The Wi-Fi password and the administration password are asked at hidden prompts. Use the public .pub key and repeat --ssh-key for more keys. The hostname has no .local and uses letters, digits and hyphens. Use --no-wifi instead of --ssid/--country for an Ethernet-only board. --user-password sets the password for sudo and local login; it does not enable password SSH. If the image is compressed, extract it first with xz -dk.
  2. Check the outputIt writes my-duo.img and my-duo.img.sha256 and refuses to overwrite existing files. The original image is left unchanged.
  3. Write the cardUse one of:
    • balenaEtcher: Flash from file, choose my-duo.img, choose the card, Flash.
    • Raspberry Pi Imager: Choose OS → Use custom, pick the image, choose the card. Do not apply OS customisation.
    • Linux helper: sudo scripts/flash.sh /dev/sdX ~/Downloads/my-duo.img. It checks the checksum, refuses system disks and asks you to retype the device.
    • dd on Linux: 
      $ lsblk -o NAME,SIZE,MODEL,TRAN      # card out
# insert the card
$ lsblk -o NAME,SIZE,MODEL,TRAN      # card in: the new line is your card, e.g. sdb
$ sudo dd if=$HOME/Downloads/my-duo.img of=/dev/sdX bs=4M conv=fsync status=progress
$ sync

Option C: write the stock image, then configure the card

If the card is already flashed, mount its boot volume and add the settings to it. The board imports them on first boot:

$ python3 scripts/configure-image.py --boot-dir /path/to/boot \
    --ssid "Your network" --country CO \
    --hostname robot-01 --ssh-key ~/.ssh/id_ed25519.pub --user-password

This writes playground/wifi.conf, hostname, authorized_keys and user.conf on the FAT volume and refuses to replace existing ones. Eject the card safely afterwards. On first boot the Wi-Fi profile is stored with root-only permissions, the hostname is applied, the keys are installed for the beitlab user, and the import files are removed. The password is carried only as a salted SHA-512 hash.

Option D: no preconfiguration

  • Ethernet: plug in the cable. DHCP needs no setup.
  • Serial wizard: attach a 3.3 V adapter to J22 at 115200 8N1 before powering on. If neither Ethernet nor Wi-Fi connects within about 15 seconds, the console asks Connect to Wi-Fi now? [y/N]. Answer y within 30 seconds, then enter the SSID and the hidden password. It tries three times and saves a working profile for later boots. q or Ctrl-C cancels. Later, sudo beitlab-wifi-setup reopens it.

Without a provisioned key or password the beitlab account stays locked, so SSH will not work. Prefer options A to C when you want to log in over the network.

3. Boot the board

  1. Set the boot switch to ARMWith the board unpowered, move the Duo S boot switch to ARM. If the serial log starts with C instead of the ARM boot messages, the switch is on RISC-V: power off, move it and try again.
  2. Insert the cardPut the flashed microSD card into the Duo S.
  3. Power it
    • Bare Duo S: power it from its USB-C port.
    • Duo S on the Robotics Board: power the board, as in First steps. Do not also plug in USB-C. Use Ethernet or Wi-Fi for the network.
  4. Wait about 30 secondsLinux boots, the Wi-Fi driver loads, the saved network connects and the rtos-agent is enabled. Lines starting with RT: on the serial console come from the small core. That is expected.

4. Connect and verify

$ ping beitlab-milkv-duo.local            # or robot-01.local if you set a hostname
$ ssh beitlab@beitlab-milkv-duo.local        # uses your provisioned key
$ sudo -n /usr/libexec/playground/rtos-control status

The status should read:

state=running
firmware=/lib/firmware/playground.elf
lock=unlocked
release=0.4.1
  1. Trust the host key onceConnect by SSH once and accept the board's fingerprint, ideally after comparing it with ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub on the serial console. PlatformIO rejects unknown or changed host keys.
  2. HostnamesIf you set a hostname, use it here and run export PIO_DUO_HOST=robot-01.local so PlatformIO talks to the same board.
  3. If .local does not resolveLook up the board's IP address on your router and use ssh beitlab@<ip> with PIO_DUO_HOST=<ip>. After re-flashing a card, run ssh-keygen -R beitlab-milkv-duo.local once, because the host key changes.
  4. Check Wi-Fi explicitly 
    $ systemctl is-active beitlab-wifi.service beitlab-wpa.service dhcpcd.service
$ sudo wpa_cli -i wlan0 status           # wpa_state=COMPLETED
$ ip -4 addr show dev wlan0
$ journalctl -b -u beitlab-wifi-import -u beitlab-wifi -u beitlab-wpa
Accounts

The login is beitlab with a private home, authenticated by your SSH key. Root cannot log in over SSH and there is no shared or default password. Administration uses sudo with the password you chose before flashing. Add --ssh-password-login to configure-image.py only if you deliberately want password SSH.

5. Build and upload your first program

On the PC, once:

$ scripts/fetch-freertos.sh            # FreeRTOS tree and the C906 toolchain at the pinned commit; builds the vendor libraries

Then upload the hello example:

$ cd examples/platformio/hello
$ pio run -t upload                    # build, copy over SSH, restart the C906
$ pio run -t rtmonitor                 # C906 log over SSH, Ctrl-C to stop

The upload ends with loaded /lib/firmware/playground.elf sha256=... state=running. The monitor prints a line every second:

RTD: playground hello Nov 19 2026 16:42:07

Linux keeps running: your SSH sessions stay open and uptime does not reset. To target another board once, use PIO_DUO_HOST=192.168.1.50 pio run -t upload. PIO_DUO_USER and PIO_DUO_PASS are also available; a key is preferred over a password.

Upload exit codeMeaning
0Loaded and running.
2Not a valid C906 ELF. Nothing changed.
3The board is locked (see the carrier note).
4The program did not start. The starter firmware is running instead.
Checkpoint

You see the hello banner in rtmonitor. You now have the full loop: edit C on the PC, pio run -t upload, read the log. Next: try the examples or write your own.

6. On the Robotics Board: lock before the robot moves

On the carrier, the C906 owns the motor, PWM, SPI and I²C pins once robot firmware runs, and every upload or recover restarts it. Lock the board before the wheels can move:

$ ssh beitlab@beitlab-milkv-duo.local sudo -n /usr/libexec/playground/rtos-control lock
# only with the E-stop open:
$ ssh beitlab@beitlab-milkv-duo.local sudo -n /usr/libexec/playground/rtos-control unlock

While locked, uploads fail with locked and PlatformIO shows *** [upload] Error 3. The agent cannot see the E-stop, because those pins belong to the C906. Keep the E-stop open, the wheels off the ground and a battery disconnect within reach while you try new code.

Recovery and troubleshooting

SymptomWhat to do
A program wedged the C906ssh beitlab@beitlab-milkv-duo.local sudo -n /usr/libexec/playground/rtos-control recover restarts the starter firmware. Linux stays up.
No ping, nothing on serialWrite the card again. Check the boot switch is on ARM.
Serial log starts with CThe boot switch is on RISC-V. Power off, set ARM, power on.
Board not on Wi-FiPlug in Ethernet or open the J22 console and run sudo beitlab-wifi-setup. Check the country code, the password length (8–63 bytes) and the journal command in step 4.
Permission denied (publickey)The image was not given your public key. Re-flash with --ssh-key, or add the key to the card as in option C.
PlatformIO host-key errorConnect by SSH once to trust the key. After a re-flash, run ssh-keygen -R <host> and connect again.
pio cannot find the toolchainRun scripts/fetch-freertos.sh on a Linux x86_64 machine or in WSL2.
