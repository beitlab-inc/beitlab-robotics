Robotics Board · Development SDK

Examples and platforms

One SDK, two hardware platforms. The same PlatformIO workflow builds a C906 program for the Robotics Board or for a Milk-V Duo S on its own. A hardware profile chosen in each example decides which pins your code may touch. Every example below lives in examples/platformio/ of the duo-s-playground repository.

Needs a flashed board: get it and flash itpio run -t uploadpio run -t rtmonitor

The two platforms

Platform 1

Robotics Board v0.11

The Duo S fitted on the Beitlab carrier: motor drivers, IMU, angle sensors, servos and a latched E-stop. The C906 owns the real-time pins. Profile beitlab_robotics_rev011.

Platform 2

Milk-V Duo S standalone

The Duo S on its own, powered over USB-C, with the 3.3 V J3 header free for your own wiring. Profile duos_bare.

Pick the right profile

The profile is chosen at build time. The first version of the SDK does not detect the carrier. Building with duos_bare while the Duo S sits on the Robotics Board can grant access to robot connections, so a program built for the bare board must never be uploaded to the carrier. When unsure, use the carrier profile: it refuses everything the robot owns. Direct SDK or MMIO calls bypass the checked API, so keep your code on the pg_gpio and beitlabduino functions.

Run any example

With the board flashed, connected and unlocked, and the toolchain installed with scripts/fetch-freertos.sh (see the SDK page):

$ cd duo-s-playground/examples/platformio/<example>
$ pio run -t upload       # compile, upload over SSH, restart the C906; exits 0 on success
$ pio run -t rtmonitor    # stream the C906 log; Ctrl-C leaves the program running

Each example selects its own profile in its platformio.ini. The shared settings in examples/platformio/common/playground.ini default to the carrier profile for projects that omit one. Uploading replaces whatever program is running on the C906.

Standalone Milk-V Duo S

These use custom_profile = duos_bare. Do not upload them to a Duo S that is fitted on the Robotics Board.

hello

A FreeRTOS task prints playground hello <build-id> once a second. The build id is the compile date and time, so you can tell which build is running. It touches no GPIO and is the safest first upload.

$ cd examples/platformio/hello && pio run -t upload && pio run -t rtmonitor
RTD: playground hello Nov 19 2026 16:42:07

On the serial console the same line has an RT: prefix. Linux keeps running; only the small core restarts.

blink

Toggles one GPIO at 1 Hz, 500 ms each way. The pad comes from pin.h, and the shipped file uses the on-board LED:

#define PLAYGROUND_GPIO_ENABLE 1
#define PLAYGROUND_GPIO_PAD "A29"

With PLAYGROUND_GPIO_ENABLE 0 it prints heartbeat idle and touches nothing; that is how the sibling heartbeat example ships, with an empty pad. Edit pin.h for another pad only after checking the schematic: ports A to D are supported, the pad must already be muxed to GPIO, and the profile must allow it. A refused pad prints the profile and the reason.

mailbox_ping

The C906 waits for mailbox command 0x40 and replies with the nonce plus one. It proves that Linux and the small core can talk.

$ cd examples/platformio/mailbox_ping && pio run -t upload
$ ./host_ping.sh 7                        # from the PC; on the board: host_ping 7
host_ping: reply 8 == 7 + 1, ok

The monitor shows mailbox_ping nonce=7 reply=8. Exit code 3 means the reply came back unchanged, which happens when a program that does not answer ping, such as hello, is running.

beitlabduino_blink

The same LED blink as an Arduino-style program: setup() once, loop() forever.

#include "beitlabduino.h"

void setup(void)
{
	bl_pin_mode(BL_LED, BL_OUTPUT);
	bl_print("beitlabduino blink on %s", BL_LED);
}

void loop(void)
{
	bl_write(BL_LED, BL_HIGH);
	bl_delay(500);
	bl_write(BL_LED, BL_LOW);
	bl_delay(500);
}

Its platformio.ini adds one line, custom_libs = beitlabduino. Expect beitlabduino blink on A29 in the monitor and a 1 Hz LED. The LED keeps blinking after you close the monitor.

beitlabduino_mailbox

Linux controls the on-board LED through the mailbox between the two cores. The program starts blinking at 500 ms. Check in the Duo S schematic for your revision that A29 drives only the LED before running it.

CommandValueReply
0x41 LED mode0 off, 1 on, 2 blinkThe new mode
0x42 blink period50–5000 (ms per half period)The new period
Anything elseRefused (BL_CMD_ERROR)
 
$ cd examples/platformio/beitlabduino_mailbox && pio run -t upload
$ ./bl_send.sh 0x41 1       # from the PC: LED on, prints 1
$ ./bl_send.sh 0x42 100     # fast blink, prints 100
$ ./bl_send.sh 0x41 2       # back to blinking

The mailbox is hardware inside the chip, so only Linux on the Duo S can reach it. bl_send always runs on the board: bl_send.sh opens an SSH session and runs it there, or you can log in and type bl_send 0x41 1 directly, which is faster for scripts. It prints the reply value and its exit code says what happened. Image 0.4.1 includes bl_send.

beitlabduino_bmi160_j3

A BMI160 accelerometer and gyro wired to the 3.3 V J3 header: J3-3 (B20) is SCL and J3-5 (B21) is SDA. It uses the duos_bare_bmi160_j3 profile and custom_libs = beitlabduino duos_i2c4 beitlabduino_bmi160. The driver probes address 0x68 then 0x69 read-only and configures only a chip that answers with ID 0xD1. It runs at 100 Hz and prints at 10 Hz:

bmi160 a_mg=12,-8,1002 g_mdps=30,-12,5 temp_mC=24500

Units are milli-g, milli-degrees per second and milli-degrees Celsius, all integers.

Robotics Board

These use the carrier profiles. Power through the carrier, lock and unlock as in the carrier note, and keep the E-stop open while you run them. They do not compile the balance controller or any motor driver.

robotics_board

Prints the selected profile and the reservations the carrier places on the motor enable pad B19, the knee servo pad A18 and I²C4, then blinks the on-board LED A29 at 1 Hz. The reservation checks only read policy: the example never initializes or writes a carrier pad. Built with another profile, it stays idle.

$ cd examples/platformio/robotics_board && pio run -t upload && pio run -t rtmonitor
robotics board profile beitlab_robotics_rev011
B19 protected: MOT_EN_REQ motor enable request; reserved for robot firmware
A18 protected: ...
I2C4 reserved: robot IMU/ADC/accessory bus
robotics board heartbeat on A29

robotics_imu

Reads the carrier's Bosch BMI323 (I²C4, address 0x68) by polling and prints acceleration, angular rate and temperature. It is plain C and uses the beitlab_robotics_rev011_imu profile, which grants only that one address through a checked driver (custom_libs = carrier_imu). No GPIO output, SPI, PWM or LED is used. Output is also visible on J22 at 115200 8N1 with RT: prefixes.

beitlabduino_imu

The same sensor through beitlabduino typed samples, at 10 Hz. custom_libs = beitlabduino carrier_imu beitlabduino_imu with the same IMU profile:

#include "beitlabduino.h"
#include "beitlabduino_imu.h"

void loop(void)
{
	bl_imu_sample_t s;

	if (bl_imu_read(&s) == BL_IMU_SAMPLE_READY)
		bl_print("imu a_mg=%d,%d,%d g_mdps=%d,%d,%d temp_mC=%d",
			 (int)s.accel_mg[0], (int)s.accel_mg[1], (int)s.accel_mg[2],
			 (int)s.gyro_mdps[0], (int)s.gyro_mdps[1], (int)s.gyro_mdps[2],
			 (int)s.temperature_mc);
	bl_delay(100);
}

The full example calls bl_imu_begin() in setup() and retries if the sensor does not answer. With the board flat, about +1000 mg appears on the axis pointing up. Physical readings are still pending hardware qualification.

Things to know before you write code

  • Printing uses a small formatter. bl_print and pg_print understand only %d %x %s %c %p and the l modifier. %u, %f and widths such as %02x are not supported, and %u can crash the C906. Use %d for values below 231.
  • Only checked pins. bl_pin_mode() returns -1 and leaves the registers untouched when the profile refuses a pad.
  • Interrupts and shared GPIO ports. The A53 and the C906 share GPIO port registers; the FreeRTOS critical sections cannot synchronise with Linux. Hardware verification is still required for anything that toggles pins quickly.
  • The 5 ms tick. bl_delay() rounds up to whole 5 ms ticks.
